什么是 URL 编码？

                
URL 编码（百分号编码）是在特定情况下对 URI 中的信息进行编码的机制。它将特殊字符和非 ASCII 字符转换为百分号（%）后跟两个十六进制数字，代表该字符的字节值。这确保数据能通过 HTTP 安全传输而不破坏 URL 结构。

                
本工具使用浏览器内置的 encodeURIComponent 和 decodeURIComponent API 进行 UTF-8 安全的编码与解码。所有处理均在浏览器本地完成，数据不会离开你的设备。

重要说明

                
与 encodeURI 不同，encodeURIComponent 会编码所有非字母数字字符，包括 URL 结构中合法存在的字符（如 : // ? # &）。本工具使用 encodeURIComponent / decodeURIComponent，这是编码查询参数值时的正确选择。仅当你需要编码完整 URL 且不破坏其结构时，才使用 encodeURI。

                
为什么 URL 需要编码？

                
URL 本身有一套严格的字符规范，只允许字母、数字和少数保留字符（如 / ? & # =）。如果你把一个带空格、中文、特殊符号的参数直接拼进 URL，比如搜索"你好 世界"或带 & 的文本，浏览器和服务器都可能无法正确解析——空格会被截断、& 会被当成参数分隔符、中文会乱码。URL 编码的作用，就是把这些"不合法"的字符安全地转成百分号形式，让数据能原样传过去。

                
举个例子，搜索词"你好 world"会被编码成类似 %E4%BD%A0%E5%A5%BD%20world 的形式，服务器收到后再解码，就能还原出原始的中文和空格。整个过程是"可逆"的——编码只是换个写法，并没有改变信息本身。

                
encodeURI 和 encodeURIComponent 有什么区别？

                
这是开发者最容易搞混的一点。虽然两者都会做百分号编码，但作用范围不同。encodeURI 用于编码"完整的 URL 地址"，它会保留 URL 中那些有结构意义的字符（如 / ? & #），以免破坏 URL 的组成；而 encodeURIComponent 用于编码"URL 中的一个参数值"，会把几乎所有特殊字符都转义掉。如果你的目标只是某个查询参数的值（比如搜索词、用户输入），应该用 Component 版本；如果用错了，要么特殊字符没被转义，要么整个 URL 结构被破坏。

                
结果怎么用？

                
编码结果可以直接拼进 GET 请求、表单提交或 API 调用里，作为安全参数的传递形式；解码则用于把接收到的 URL 参数还原成可读文本，方便调试或读取用户输入。若你还需要做 Base64 或 JSON 处理，可配合「Base64 编解码」「JSON 格式化」工具一起使用。
