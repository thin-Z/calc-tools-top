About Text Diff

Text diff is a technique for comparing the differences between two blocks of text, helping you quickly see what was changed, removed, or added. This tool uses the LCS (Longest Common Subsequence) algorithm for line-level comparison: it aligns the two texts, treats identical lines as unchanged, and marks lines that appear in only one version as added or deleted — so the changes jump out at a glance.

Color key: Green background marks added content; Red background + strikethrough marks deleted content; White background marks unchanged content.

How Does the LCS Algorithm Work?

LCS (Longest Common Subsequence) finds the longest subsequence that appears in both sequences in the same order, then uses that common part as an anchor so the remaining differences are highlighted. Because it seeks the longest common portion, it minimizes redundant added/deleted marks, making the result closer to human intuition.

This is the approach mainstream diff tools (version control, document comparison) generally take — the main difference is granularity: some compare by character, others by line or word. This tool compares line by line, which suits whole-text comparison of code, config files, and documents.

How to Use It

1. Paste the first version into the "Original" box.
2. Paste the edited version into the "New" box.
3. Click "Diff". The result shows two side-by-side panes with colors highlighting added/deleted/unchanged.
4. The stats at the top count added, deleted, and unchanged lines so you can gauge the scope at a glance.
5. Use "Clear" to start over.

Use Cases

  • Code version comparison: see what logic changed between versions
  • Before/after article comparison: spot editorial edits
  • Document proofreading: catch missed edits, accidental deletions, or duplicated text
  • Data difference analysis: compare two configs or exported text

Common Diff Pitfalls

① Case and whitespace. Comparison is exact, so a version differing only in case or spacing is treated as a changed line. If you don't want that, normalize formatting first.
② Line endings. Windows CRLF vs. Unix LF can make lines that look identical be flagged as different.
③ Large text performance. Very long text or huge files may be slow; compare in segments to isolate issues.

How to Read the Result

Added lines usually represent edits, insertions, or supplements; deleted lines represent removed or replaced content. To pinpoint a change, combine line numbers with surrounding context; to review systematically, look at the stats first to gauge the scope, then verify section by section.
