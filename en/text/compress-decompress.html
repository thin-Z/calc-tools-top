What are Zlib, Gzip, Deflate and Brotli?

                
All four are lossless compression algorithms: decompression restores the original bytes exactly. They share the Deflate core (LZ77 + Huffman) but wrap it differently:

                
    
                    
  • Deflate — the raw compressed stream (RFC 1951) with no header or checksum; the kernel of Zlib and Gzip.
    • 
                    
  • Zlib — Deflate plus a 2-byte header and a 4-byte Adler-32 checksum (RFC 1950), common in HTTP compression, PNG and Git.
    • 
                    
  • Gzip — Deflate plus a file header and CRC-32 (RFC 1952), the standard for .gz files and most server compression.
    • 
                    
  • Brotli — a newer Google algorithm with more advanced context modeling, usually compressing better than Gzip at the same size, widely used for web fonts and static assets.
    • 
                


                
Why encode the compressed result as Hex or Base64?

                
Compression produces binary bytes that cannot be shown or copied as plain text. This tool offers two text encodings: Hex uses two characters per byte and is explicit and readable; Base64 is more compact (about 4/3 of the original). Compress with the chosen format, then paste a string in the same format to decompress. Note: compression and decompression must use the same algorithm and the same encoding format, or decompression will fail.


                
About compression ratio

                
These algorithms work best on repetitive, redundant text such as HTML, CSS, JSON, logs and config files, often shrinking it to 20%–40% of the original. Already-compressed or random data barely compresses and may even grow slightly. The more repetition, the higher the ratio — which is why long repetitive text benefits most from Brotli.


                
Data privacy

                
All compression and decompression happen locally in your browser; your input is never uploaded to any server, so it is safe for sensitive text. Speed depends on your device and the text length. The Brotli codec is loaded on demand only the first time you choose Brotli, so it does not affect using the other algorithms.


                
Common use cases

                
When debugging backend APIs, use this tool to verify and decompress Zlib/Gzip payloads returned by Java, Python or Node.js services. For frontend and ops checks, use Gzip to confirm whether a CDN enabled compression correctly. Before storing or transferring data, use Brotli for a smaller footprint. Pair it with the Base64 or URL encode tools when you also need those transforms.
