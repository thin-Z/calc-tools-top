在线图片压缩：质量与体积的权衡，不是"压得越小越好"

图片压缩的本质不是单纯"把文件变小"，而是在可接受的画质损失与更小的文件体积之间做权衡。本工具的质量滑块（默认 80%）就是这个权衡的旋钮：调低体积变小但细节变糊，调高画质更稳但文件变大。理解了这一点，你就不会再盲目追求"最低质量"，而是按用途定档。

所有压缩都在浏览器本地通过 Canvas API 完成，文件不会上传服务器，既保护隐私又能即时预览。它适合网站运营者、电商卖家、自媒体，以及任何想优化图片体积、改善加载体验的人。

有损与无损：两种"减重"机制有何不同

压缩算法分两类，机制完全不同，决定了你能压到多小、以及会不会丢信息：

维度有损（JPEG、WebP 有损、AVIF）无损（PNG）
原理丢弃人眼不敏感的高频细节（色彩子采样、量化）用更紧凑的方式重写像素，不丢任何信息
透明通道JPEG 不支持；WebP、AVIF 支持支持
体积可压到很小（照片常为原图的 1/5–1/10）照片几乎压不动，常比原 JPEG 还大
适用照片、渐变、复杂实景线条图、文字、图标、需透明者
再压缩每压一次累积损失（生成损失）可反复无损重编码

本工具对 PNG 在质量低于 100 时会智能转成 JPEG 以换取体积——代价是透明背景变白。若你必须保留透明，应保留 PNG 或改用 WebP（见下方格式对照）。

像素、DPI 与物理尺寸：屏幕显示不需要 300 DPI

注意："DPI（每英寸点数）"只在打印时才有意义。屏幕按"CSS 像素"显示，与 DPI 无关——一张 1920 像素宽的图，无论在 72 DPI 还是 300 DPI 的屏幕上，都按 1920 像素宽显示。只有打印才需要把物理尺寸换算成足够像素。

换算公式：所需像素 = 物理英寸 × DPI，而 1 英寸 = 2.54 厘米。换句话说，DPI 不凭空产生像素；若原图像素不足，调高 DPI 只会让打印出来更大更糊。

结论：准备网页图时，先按显示尺寸定像素（例如手机约 375–750 px 宽），再用本工具压到合适体积；不要被"300 DPI"误导去导出远超屏幕需要的巨图。需要改尺寸请先用 裁剪缩放 工具。

三个真实算例（使用本工具默认参数，数字来自上方实测）

算例一（相机照片直压）：一张 4000×3000 的相机 JPEG，基准体积 5.73 MB。用本工具默认质量 80压缩，输出 2574.5 KB，节省 55.1%。用于网页配图已绰绰有余。

算例二（PNG 转 JPEG 救体积）：同一张图存为无损 PNG 达 20546.8 KB。用默认质量 80 压缩，工具自动转 JPEG，输出 2574.5 KB，节省 87.5%。注意：若原 PNG 含透明区域，透明会变白；需要透明时改用 格式转换 转 WebP 保留透明。

算例三（按目标体积反推质量）：希望把 5.73 MB 原图压到"约 2 MB 且画质尚可"。查质量—体积曲线：质量 75 输出 2068.3 KB（节省 63.9%）最接近；若可接受约 1.2 MB 则用质量 60。可见"先定目标体积、再查曲线定质量"比盲调更稳。

补充问答

问：本工具压缩 PNG 时为什么会变成 JPG、透明背景没了？
答：PNG 是无损格式，低质量下有损压缩几乎无效。为拿到明显体积收益，工具在质量低于 100 时把 PNG 转为 JPEG——而 JPEG 不支持透明，原透明区被填白。要保留透明，请保留 PNG 或改 WebP、AVIF。

问：为什么质量调到 100 反而文件更大？
答：质量 100 触发近乎无损重编码，丢弃信息极少，文件比质量 95 还大约 71.7%（实测）。网页用途无需拉到 100。

问：网页用的图片，质量设多少最划算？
答：照片通常 80–85 是甜区（本工具默认 80，约省 55%）；缩略图可到 60；文字、线条图请用 PNG 或 WebP 避免锯齿。

问：同样一张图，WebP 和 JPEG 我该选哪个？
答：现代浏览器优先 WebP——同体积下细节更好、同画质下体积更小（实测 WebP q80 比 JPEG q85 还小）。需兼容老旧系统再备一份 JPEG。可用 格式转换 互转。

问：屏幕显示到底需要多少 DPI？300 DPI 有必要吗？
答：屏幕按 CSS 像素显示，与 DPI 无关；300 DPI 只用于打印。网页图按显示像素定尺寸即可，无需追 300 DPI。详见上方换算表。
